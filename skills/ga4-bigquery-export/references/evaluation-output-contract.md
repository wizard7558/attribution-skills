# GA4 evaluation projection interface

This is a deterministic projection interface for the evaluation, not another producer API. Its shared section plus the relevant group section are included verbatim in each fixed prompt for **both** conditions. Operational rules are in the separately supplied skill context when present. No fixture answers are included here.

## Shared interface

Return one JSON object `{"cases":[{"case":string,"result":...}]}`. Preserve A–H case order. Inputs share named pools; a case references an entire observed population or selects rows from its output. A selector never starts a different scan. Apply each pool's inclusive daily `window`; for these fixture encodings, `event_date` also supplies its daily suffix. Missing optional input fields mean SQL NULL, not zero. Key-event names are explicit. Source scope is opaque. Neutral visitor/order labels are identities, not behavioral instructions; retain their exact bytes, including surrounding whitespace. Do not alter URL/parameter values.

Input encodings: `session_events` uses visitor→user_pseudo_id, session→integer ga_session_id, number→integer ga_session_number, timestamp→INT64 event_timestamp, event→event_name, url/referrer→page_location/page_referrer, engaged→string session_engaged, engagement_ms→integer engagement_time_msec. Source/medium/campaign/native are one cross-channel struct; manual_source/manual_medium/manual_campaign are its manual counterpart; gclid/dclid/srsltid are collected fields; transaction/revenue are ecommerce transaction_id/USD purchase revenue. `parameter_events` preserves its ordered typed event_params literally; user/timestamp map to visitor/timestamp, with transaction/revenue and event_value_in_usd as named. Its native source and collected structs are NULL. `purchase_events` carries native qualification and a selected payload: revenue_usd, tax_usd, shipping_usd, native_revenue, currency, quantities and ordered items map to ecommerce/item fields of the same meaning. Source nonfinite FLOAT64 values are encoded by strings `NaN`, `Infinity` or `-Infinity`; they are not output JSON numbers.

Output counts, offsets, selected integer IDs and raw event_timestamp are JSON integers. FLOAT64 amounts, engagement time and percentages are JSON numbers or NULL; approximate checks allow absolute error 1e-9, including equivalent integer/decimal spelling. Do not emit Boolean values as numbers. Transport rows separately preserve all INT64/decimal/TIMESTAMP strings exactly. Dates are YYYY-MM-DD. Arrays require exact cardinality and ordering; do not invent absent rows. Include every required field and no extras. Nullable fields remain nullable irrespective of a particular case. Native states/reasons below have exact spelling. No SHA calculation is requested.

## sessions-and-source-evidence

Equal event timestamps use the native selected-base JSON field order: event_date, user_pseudo_id, ga_session_id, ga_session_number, event_name, event_timestamp, page_location, page_referrer, session_engaged, engagement_time_msec, gclid, dclid, srsltid, source_evidence, transaction_id, purchase_revenue_in_usd. source_evidence has source, medium, campaign, native_channel in that order. Fields are present with their selected typed values, including NULL. This ordering information is public; no hidden event identifier or unprovided field breaks ties.

`sessions` returns the selected session rows in the input session_keys order. Each row has source_system, source_scope, session_key, visitor_key, event_date, landing_page_location, landing_page_path, session_source, session_medium, engaged, key_events and events. Native scope is retained; NULL strings remain NULL.

`landing` returns the full declared top-20 output: source_system, source_scope, landing_page_path, sessions, engaged_sessions, key_events. Order by sessions descending, then source_system/source_scope/path ascending, NULL first. `traffic` returns source_system, source_scope, session_last_click_source, session_last_click_medium, landing_url_status, landing_utm_source, landing_utm_medium, landing_utm_campaign, sessions. Order by sessions descending then all preceding group fields ascending, NULL first. URL status vocabulary is `missing`, `invalid`, `valid`; UTM strings preserve case.

`channels` returns `{channels:[{visitor_key,channel}],retained_clicks:[{name,value}]}`. Channel rows follow visitor_keys order. The click_visitor identifies one existing native session; preserve all supported click fields in this order: gclid, dclid, gbraid, wbraid, msclkid, fbclid, ttclid, rdt_cid, li_fat_id, twclid, epik, sccid, srsltid. Canonical channel vocabulary is Paid Search, Paid Social, Paid Other, Organic Search, Organic Social, Email, SMS, Direct, Referral, Affiliate, Other. Click values are nullable strings.

`scope_review` returns each named question as a field. session_identity_fields is an ordered list of output field names; splits_platform_stream asks whether grouping separates those dimensions; reporting_timezone asks what timezone the unconfigured report declares; engagement_measure uses `observed_proxy` or `ui_exact`; complete_beyond_window asks whether the scan certifies complete sessions outside it; new_users_measure uses `first_session_rows` or `distinct_people`; same_person_across_sources and native_channel_is_canonical ask whether those equivalences are established; sample limits are integers, and landing_groups_by_date asks whether date is a final grouping field.

## parameters-and-observation-boundaries

`parameters` selects helper rows by ordered (user_pseudo_id,event_timestamp) row_keys. Return source_system, source_scope, event_date, event_timestamp, event_name, user_pseudo_id, ga_session_id, page_location, ga_session_id_duplicate_count, page_location_duplicate_count, session_engaged, engagement_time_msec, session_engaged_duplicate_count and engagement_time_msec_duplicate_count. Duplicate counts are additional matching records beyond the first. These common fields must match the inline extraction, even when typed NULL wins.

`key_events` returns source_system, source_scope, user_pseudo_id, ga_session_id, event_date, event_name, event_timestamp, event_value_in_usd and session_key for the declared top-1,000 ordered raw occurrences. Order timestamp, source/scope/visitor/session, event_name, event_date and event_value_in_usd, ascending with NULL first; identical projected occurrences remain repeated. This explicit projection ordering uses no hidden evidence field. The old CLI event_ts display is excluded from this projection.

`parameter_sessions` returns source_system, source_scope, session_key, event_date, landing_page_location, events, engaged, key_events, engagement_time_sec; order source/scope/session_key ascending.

`daily_observations` returns the daily_observations array; `identifier_and_spans` returns the two objects identifier_observation and session_date_spans; `observations` returns all three. Daily rows contain source_system, source_scope, table_date, observed_event_rows, table_existence, export_completeness, observation_scope, limitations and are date ascending. Identifier observation contains source_system, source_scope, total_events, null_user_pseudo_id_events, missing_session_id_events, pct_null_user, missing_identifier_cause, observation_scope, limitations. Spans contains source_system, source_scope, total_sessions, sessions_crossing_midnight, pct_crossing_midnight, observation_scope, limitations. Percentages are rounded to two decimal places and NULL on zero denominator.

State vocabulary includes `unknown`; these reports do not infer known existence, completeness or cause. Exact observation_scope literals by component are `daily_export_rows_in_supplied_window`, `all_observed_events_in_supplied_window`, `qualified_sessions_observed_in_supplied_window`. Exact limitations literals are respectively `row_counts_do_not_establish_table_existence_completeness_or_lag`, `identifier_absence_does_not_establish_consent_cause`, `window_censored_date_spans_do_not_establish_lifetime_sessions_or_explain_ui_differences`.

## transactions-and-execution

`ecommerce` projects daily_summary, qualified_transactions, item_lines, unkeyed_evidence and diagnostics. `ecommerce_totals` returns an ordered array `{pool,daily_summary,diagnostics}` in requested pool order. Use only revenue_usd from native money arrays in these projections; tax/shipping/native fields still participate in payload conflict comparison.

Daily rows retain event_date, qualified_transaction_count, all_population_unique_purchase_count, known_subtotal, value and reasons; the last three project native revenue_usd. Daily rows are date ascending. Qualified rows retain platform, stream_id, user_pseudo_id, transaction_id, event_date, occurrence_count, payload_variant_count, status and revenue `{value,status}`. Source_system/source_scope remain the pool's supplied report scope, not additional row partitions. Transaction status is `accepted` or `conflict`; amount status is `known`, `unknown`, `invalid`, `conflict`. Order platform/stream/visitor/transaction ascending.

Item rows retain platform, stream_id, user_pseudo_id, transaction_id, item_offset, quantity `{value,status}` and revenue_usd `{value,status}`. Order that qualified key then item_offset. Quantity status is known or unknown. Unkeyed rows retain platform, stream_id, user_pseudo_id, transaction_id, event_date, event_timestamp_micros as a string, occurrence_count and reasons. Use the neutral projection order: event_date, timestamp as integer, platform, stream_id, user_pseudo_id, transaction_id, occurrence_count, then the reasons list lexicographically. NULL sorts first; strings use UTF-8 lexical order. No hidden native JSON serialization is needed to order projected answers.

Diagnostics retains observed_purchase_events, qualified_purchase_events, unkeyed_purchase_events, qualified_transaction_count, conflicting_transaction_count, collapsed_duplicate_events, item_line_count. Native payload variants and additional bookkeeping remain in the private full-output proof, outside this projection. Unkeyed reasons, in order when applicable, are `missing_platform`, `missing_stream_id`, `missing_user_pseudo_id`, `missing_transaction_id`. Daily revenue reasons, in order when applicable, are `numeric_failure`, `unkeyed_window_evidence`, `conflicting_payload`, `invalid_amount`, `unknown_amount`.

`channel_daily` returns event_date, channel, sessions, engaged_sessions, new_users, key_events, purchases, purchase_revenue_usd, revenue_status, purchase_events_without_transaction_id and native_channel_groups. Order event_date then sessions descending then channel; native labels are sorted. Native revenue_status vocabulary is `unkeyed_purchases`, `no_purchases`, `unknown`, `complete`. This is the separate session/transaction policy, not the ecommerce conflict policy.

`execution_configuration` returns configurations in input order as `{accepted,billing_project,location,maximum_bytes_billed}`. Invalid configurations have accepted=false and the other fields NULL. Policy answers use each question's Boolean field. `result_pages` returns each trial as `{accepted,rows,total_rows,page_count}`; accepted collections contain complete decoded rows, exact totalRows string and integer page count. Rejected collections have accepted=false and the other fields NULL; never treat a partial collection as success. Each page fragment inherits the supplied shared identity as jobReference and shared schema; all other response fields are explicit. Page responses are input observations, not expected answers.

`resume` returns the named count/Boolean/state questions. Initial and unchanged-resume submission counts count actual query submissions, not observations. Same-handles and original-report questions concern identity and byte preservation. Change-rejected fields describe exact config/wrapper/template validation. Missing/failed-handle replacement counts count new queries for those recorded handles. State vocabulary is `completed`, `query_failed`, `retrieval_pending_or_failed`. No real provider, credential, model or BigQuery request is part of these offline execution scenarios.
