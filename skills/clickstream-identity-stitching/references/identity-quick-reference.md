# Identity decision reference

This compact reference summarizes the accepted [identity](identity-contract.md), [graph](graph-contract.md), and [webhook](webhook-contract.md) contracts. It contains general rules, not case answers. Native modules remain authoritative.

## Canonicalization and touches

Email is trimmed/lowercased with dots and plus tags preserved, including Gmail. It needs one @, nonempty local part, dotted nonempty domain and no whitespace. Phone needs explicit + country code, 8–15 digits, nonzero first digit; supported formatting and trailing extension are removed. Invalid primitive identities return null. Hash canonical email/phone with SHA-256; no scope salt. These are local identity rules, not interchangeable destination CAPI rules. Scope authorization remains separate from digest equality.

Dedup keys are (system, scope, visitor, touch); visitor state is isolated by (system, scope, visitor). Exact duplicate records under a key are suppressed as `duplicate_idempotent`; conflicting records reject. Validate every row, including excluded/replayed rows. Existing accepted history participates in comparisons but is not returned as newly accepted touches. An identical older key may replay; a previously unseen event older than the latest existing touch in its qualified visitor requires full chronological replay.

Sort by exact epoch nanoseconds and then full JSON-encoded qualified key using native locale comparison. Valid timestamp syntax has a four-digit Gregorian year (0000–9999), uppercase T, seconds, optional 1–9 fractional digits, and Z or an offset no greater than 14:00. Year 0000 is leap; 0100 is not. Equivalent offsets describe the same instant. Never round through milliseconds.

Signature = channel + campaign + recognized click-ID names/values. Campaign decodes at most five URI passes, converts plus to space, trims and lowercases. Click values decode at most five passes and trim, preserving case and plus; blank/null/undefined placeholders are ignored. Different campaigns, channels, or opaque click IDs remain different. Recognized click names: dclid, gclid, gbraid, wbraid, msclkid, fbclid, ttclid, rdt_cid, li_fat_id, twclid, epik, sccid, srsltid. Preserve intervening A → B → A journeys: only the immediately preceding accepted signature can suppress. Equal signature is suppressed strictly below 1800 seconds; exactly 1800 is accepted. Suppressed events never extend the window. Direct is accepted only as the first accepted attribution touch for that qualified visitor, including existing history. This does not redefine collector sessions.

## Graph

Bindings explicitly connect visitor system/scope to contact system/scope, even if names coincide. Contacts are qualified by system/scope/contact key. Raw mode canonicalizes and hashes valid email/phone and rejects supplied non-null hash fields. Explicit `canonical_sha256_v1` mode accepts absent/null or exact lowercase 64-hex hashes, rejects non-null raw identities and never rehashes; hash preimages cannot be verified from the digest. Contacts may lack identity; identifies must have at least one valid identity. Malformed supplied identities reject even when unauthorized or future. Identical qualified records collapse; conflicts reject.

Union email and phone matches in all authorized contact scopes. Exactly one contact yields an immutable edge for that observation; none is unresolved; multiple are ambiguous and yield no edge. Never invent/merge contacts or overwrite earlier observations. A second matched observation on a shared device remains separate evidence.

Exclude identifies and touches after as_of using exact nanoseconds. An edge supports a touch if edge <= as_of, touch <= as_of, and touch >= edge - lookback_days, inclusively. Lookback is a positive finite Number interpreted as the exact rational decimal in Number.toString(), including scientific notation and subnanosecond intervals. Earlier edges continue supporting later touches. This is an edge-anchored retrospective limit, not a report-age cutoff.

Global visitor contacts include every matched edge through as_of, independent of a particular touch's eligibility. If multiple global contacts exist and the touch has an eligible edge, it is ambiguous with reason `shared_device`; list all global contacts but only eligible evidence keys. No eligible edge means unresolved, no contacts/evidence and no reason, even for a globally shared device. Ambiguous observations create neither edges nor global ownership. Global ambiguity lists do not authorize credit. Preserve raw timestamp text in native outputs; projected keys still retain full qualification.

Never infer identity from IP, URL proximity or bare GA4/PostHog/Segment/Snowplow IDs. Each source needs a verified identity adapter and explicit binding; distinguish GA4 property/stream, PostHog project, Segment workspace/source and Snowplow collector/app scope and native identifier types. Graph outputs exclude raw identities/arbitrary metadata. Only established graph edges can supply webhook recent identity evidence.

## Verified webhooks and durable receipts

The pure webhook resolver validates all rows before matching or replay, including malformed raw identities and conflicting qualified visitor/page/evidence records. Its accepted timestamp/window arithmetic is millisecond based; do not silently substitute graph nanosecond semantics. Policy explicitly supplies nonnegative page/recent minute windows and four confidence values in [0,1]. These are operational scores, not calibrated probabilities.

Resolve in order: known explicit visitor in exact capture system/scope (no age condition); supplied exact page-event key for a known same-scope visitor with event_at in the inclusive submission-minus-page-window through submission interval; unique same-scope known visitor in the email OR phone evidence union; deterministic new scoped visitor. Unknown explicit visitor adds `visitor_field_unknown` and continues. Missing page key skips that method; supplied missing/out-of-window/unknown-visitor events add the corresponding page diagnostic and continue. Page diagnostics take the native validation sequence: missing key lookup, timestamp, then known visitor.

Recent matching requires BOTH evidence_at and visitor.last_seen_at within the inclusive recent interval and no future timestamp. Missing identity adds `identity_unavailable`; an empty eligible union adds `recent_visitor_no_match`; multiple distinct visitors add `recent_visitor_ambiguous` with sorted qualified candidates then fall through to creation. Never choose the newest among ambiguous visitors. Two matching kinds for the same qualified visitor count once. New visitor is scoped by capture system/scope/provider/submission key and supplies no prior behavior or contact credit.

Receipt identity includes capture system/scope/provider/submission key. Its SHA-256 fingerprint covers normalized semantic submission fields and policy, excluding candidate state and arbitrary metadata. Precomputed fingerprint evidence may be compared directly. Equivalent canonical identities and equivalent timestamp offsets replay. An identical validated receipt returns its original resolution with replayed true even after candidate state changes. Changed semantics or policy under the same receipt key reject as a payload conflict. Different provider/scope keys are independent receipts.

The caller authenticates/verifies delivery. Persist qualified receipt uniqueness, visitor/identify effects, stable business-event identity and outbox atomically. On a uniqueness race, roll back all effects, reload the winning receipt and retry only within a bounded policy; do not commit partial effects. A replay enqueues no duplicate effects. Business IDs are separate from transport retries; outbox consumers require idempotency. Pure resolution does not provide exactly-once delivery or transactional storage by itself.
